# ICPC 协会管理系统 · 协会管理模块需求规范

## 1. 背景与目标

### 1.1 背景

中南民族大学计算机学院 ICPC 协会的会员数据目前分散在 Excel 表格、微信群和纸质登记表中。入会靠线下填表，退会靠口头说明，会员身份与系统权限没有绑定；每学期考核、评优和综测证明需要人工翻找训练记录与竞赛成绩。随着协会每年招新规模扩大，人工维护成本高、数据口径不一致、权限边界模糊的问题越来越突出。

协会章程对会员分类、考核、退会和除名均有明确规定，但这些规则尚未落到系统中。需要一个以“会员”为主数据的模块，把会员全生命周期管理线上化，并与系统角色权限联动。

### 1.2 目标

构建协会管理模块，覆盖会员从入会申请、身份分类、考核、档案到退会/除名的完整生命周期，实现：

- 会员信息一处维护、全局复用，消除多份 Excel 并存；
- 入会、退会、考核全程线上审批，操作留痕、结果可追溯；
- 会员身份变化自动同步系统角色，权限随身份即时生效；
- 会员档案自动聚合训练、竞赛、考核记录，支撑评优与材料申报；
- 为后续题库、训练、集训、赛事模块提供统一、可信的会员主数据。

### 1.3 目标用户

- **主要用户**：干事（会员信息录入、入会审批、档案查询）、部长/副部长（退会审批、考核结果审核）、会长/副会长（全局管理、删除与除名）
- **主要使用者**：观察会员、正式会员、竞赛实验室成员（提交入会/退会申请、查看本人档案与考核结果）
- **监督者**：指导老师（全局查看、重大事项审批）

## 2. 功能范围

### 2.1 做什么（本期）

#### 会员信息管理

- 维护会员基本信息：学号、姓名、专业、年级、手机号、邮箱、头像、会员类型、所属部门、入会日期、会员状态。
- 支持分页查询，按姓名/学号模糊搜索，按会员类型、年级、部门、状态组合筛选。
- 支持新增、查看详情、修改、逻辑删除会员。
- 学号全局唯一；新增会员时若学号已存在，拒绝创建并提示“该学号已存在会员记录”。
- 新增会员或入会审批通过时，以默认密码 `123456` 初始化账号，密码使用 BCrypt 加密存储，任何接口不得返回密码字段。
- 普通会员仅可修改本人姓名、专业、年级、手机号、邮箱、头像；会员类型、状态、部门仅干事及以上角色可修改。
- 删除会员仅会长/副会长可执行，采用逻辑删除，同时将会员状态置为“已除名”并回收全部角色。

#### 会员分类与权限

- 会员类型分为：观察会员、正式会员、竞赛实验室成员。
- 管理角色分为：队长、干事、助理教练、部长/副部长、会长/副会长、指导老师。
- 会员类型与基础角色一一映射：`OBSERVE_MEMBER`、`MEMBER`、`LAB_MEMBER`。
- 会员类型变更时自动同步基础角色，保留干事、部长等管理角色，避免误删管理权限。
- 权限按角色层级继承：指导老师 > 会长/副会长 > 部长/副部长 > 助理教练 > 干事 > 队长 > 实验室成员 > 正式会员 > 观察会员。
- 未登录访问受保护接口返回 401，越权操作返回 403。

#### 入会流程管理

- 入会申请对未入会用户开放，无需登录；采集学号、姓名、专业、年级、手机号、邮箱、入会动机。
- 同一学号已是协会会员，或已有待审批入会申请时，拒绝重复提交。
- 干事及以上角色可查看待审批列表，执行“通过/驳回”并填写审批备注。
- 审批通过后自动创建观察会员档案、分配观察会员角色，并回填申请人信息；驳回时保留驳回原因。
- 申请状态流转：`PENDING` 待审核 → `APPROVED` 通过 / `REJECTED` 驳回；已处理申请不可重复审批。
- 面试安排、录取通知、实体会员证发放属于线下环节，系统只记录审批结果，不做线上流程编排。

#### 退会 / 除名管理

- 正式会员可提交退会申请并填写退会原因；仅状态为 `ACTIVE` 的会员可提交，且不允许重复提交待审批申请。
- 退会审批由部长及以上角色负责；审批通过后会员状态置为 `RESIGNED`，并清空该会员全部角色，使其现有 Token 立即失去受保护接口的访问能力。
- 违规除名由会长/副会长直接操作，状态置为 `REMOVED`，逻辑删除会员并保留历史记录。
- 审批单记录申请人、审批人、审批时间、审批意见，纳入会员档案备查。

#### 考核管理

- 支持创建学期考核、观察期考核等考核任务，字段包括名称、类型、说明、起止时间、及格线。
- 考核存在“草稿/已发布”状态：草稿可修改、删除；发布后对普通会员可见。
- 助理教练及以上角色可批量录入或更新考核成绩，系统按及格线自动判定“通过/不通过”。
- 考核结果需部长及以上角色审核后方可公示；会员仅可查看本人已发布考核的结果。
- 考核类型覆盖学期注册、训练考核、观察期转正考核。
- 成绩以人工录入为准，不接入训练/OJ 数据做自动加权换算。

#### 会员档案

- 档案聚合展示：基本信息、角色、训练记录、竞赛成绩、考核记录。
- 本人或干事及以上角色可查看档案；管理员可按会员导出档案，用于评优、材料申报。
- 档案为只读聚合视图，不允许在档案页直接篡改来源业务数据。
- 奖惩记录在 FR-MEM-006 上线前预留展示区块，无数据时显示“暂无记录”，不得报错。

### 2.2 不做什么（本期明确排除）

- **不做** FR-MEM-006 奖惩管理：奖励/处分记录的增删改查与综测证明导出留待后续迭代，接口契约在《接口手册》中预留。
- **不做** FR-MEM-008 数据统计分析：按年级/专业/部门/类型的会员结构报表与人员流动统计留待后续迭代。
- **不做** 线下环节线上化：面试安排、现场面试评分、录取短信、实体会员证制作与发放。
- **不做** 学校统一身份认证（CAS/统一登录）对接，本期使用学号 + 密码登录。
- **不做** 微信/QQ/邮件自动通知推送，审批结果仅在系统内展示。
- **不做** 与学校综测系统的接口对接和综测加分自动计算。
- **不做** 考核自动阅卷，以及与 OJ/训练成绩的自动换算。
- **不做** 自定义报表设计器、BI 大屏和跨年度大数据分析。
- **不做** 多协会/多租户，系统仅服务中南民族大学计算机学院 ICPC 协会。
- **不做** 会员端移动 App / 小程序，仅提供响应式 Web 页面。
- **不做** 历史会员数据自动迁移工具，首次数据由管理员批量导入或运维脚本处理。

### 2.3 技术约束

- **架构**：B/S 架构；前端 Vue 3 + Element Plus + Pinia + Vue Router + Axios；后端 Spring Boot 3.2 + Spring Security + JWT + MyBatis-Plus。
- **数据库**：MySQL 8.0；Redis 7 用于会话与热点数据缓存；Nginx 反向代理。
- **接口规范**：RESTful，基础路径 `/api/v1`；统一响应 `{ code, message, data }`；分页响应 `{ total, page, size, records }`；错误码使用 400/401/403/404/409/422/500。
- **认证方式**：JWT Bearer Token，默认 2 小时过期；密码 BCrypt 加密存储。
- **权限模型**：RBAC + 角色层级；后端使用 `@PreAuthorize` 做接口级拦截，前端按角色动态渲染菜单与操作按钮。
- **数据规则**：会员删除为逻辑删除；新增/修改/删除会员、提交退会、审批等关键操作写入操作日志。
- **字段校验**：学号 6-12 位数字且全局唯一；手机号符合 `1[3-9]\d{9}`；邮箱符合标准格式；必填字段为空返回 400。
- **分页约束**：默认 `page=1`、`size=20`，`size` 上限 100，非法值按默认值处理。
- **事务约束**：入会审批创建会员与角色绑定、退会审批更新状态与回收角色，必须在同一事务内完成，任一步失败整体回滚。

## 3. 验收标准

### 3.1 功能验收

#### 会员信息管理

- [ ] 可按姓名或学号模糊搜索会员，并组合会员类型、年级、部门、状态筛选，分页结果正确
- [ ] 新增会员后，会员列表与详情可查到该会员，默认密码为 `123456` 且数据库中为 BCrypt 密文
- [ ] 使用已存在的学号新增会员时，返回 409 并提示“该学号已存在会员记录”
- [ ] 普通会员修改本人姓名、手机号、邮箱可成功；修改会员类型、状态、部门返回 403
- [ ] 干事及以上角色可修改任意会员的类型、状态、部门
- [ ] 会长删除会员后，该会员不再出现在列表和详情中，数据库记录仍保留且 `deleted=1`
- [ ] 非会长角色调用删除会员接口返回 403

#### 会员分类与权限

- [ ] 新增观察会员、正式会员、实验室成员时，分别自动获得 `OBSERVE_MEMBER`、`MEMBER`、`LAB_MEMBER` 角色
- [ ] 将会员类型从观察会员改为正式会员后，基础角色同步为 `MEMBER`，原有干事/部长等管理角色保留
- [ ] 未携带 Token 访问会员管理接口返回 401
- [ ] 观察会员调用新增会员、删除会员、查看他人档案接口均返回 403

#### 入会流程管理

- [ ] 未登录用户可提交入会申请，申请状态为 `PENDING`
- [ ] 已入会学号再次提交入会申请返回 409
- [ ] 同一学号存在待审批申请时再次提交返回 409
- [ ] 干事可查看入会申请列表并审批通过，系统自动创建观察会员档案并分配观察会员角色
- [ ] 审批驳回后申请状态为 `REJECTED`，审批备注被保存并可查询
- [ ] 已审批的申请再次审批返回 409

#### 退会 / 除名管理

- [ ] `ACTIVE` 会员可提交退会申请，申请类型为 `RESIGN`、状态为 `PENDING`
- [ ] 非 `ACTIVE` 会员提交退会申请返回 409
- [ ] 存在待审批退会申请时重复提交返回 409
- [ ] 部长及以上审批通过退会申请后，会员状态变为 `RESIGNED`，全部角色被清空
- [ ] 退会审批通过后，该会员原有 Token 访问受保护接口返回 401 或 403
- [ ] 干事审批退会申请返回 403

#### 考核管理

- [ ] 助理教练可创建考核，草稿状态可修改、删除，发布后普通会员可见
- [ ] 可批量录入考核成绩，系统按及格线自动判定“通过/不通过”
- [ ] 重复录入同一会员成绩时执行更新，不产生重复记录
- [ ] 考核结果经部长及以上审核后方可公示
- [ ] 会员只能查看本人考核结果，查看他人结果返回 403

#### 会员档案

- [ ] 本人可查看自己的完整档案，干事及以上可查看任意会员档案
- [ ] 档案正确聚合基本信息、角色、训练记录、竞赛成绩与考核记录
- [ ] 普通会员查看他人档案返回 403
- [ ] 奖惩记录为空时，档案页显示“暂无记录”，接口返回空数组而非报错

### 3.2 性能验收

- [ ] 会员列表在 1 万条会员数据、默认分页条件下响应时间 ≤ 2 秒
- [ ] 会员详情与档案聚合查询响应时间 ≤ 2 秒
- [ ] 新增、修改、审批等单次写操作响应时间 ≤ 3 秒
- [ ] 100 并发用户下，会员查询与审批接口错误率 < 1%，无请求超时
- [ ] 同一申请被并发审批时，仅 1 次成功，其余请求返回 409
- [ ] 审批事务中任一步失败时，会员创建/状态变更与角色变更同时回滚

### 3.3 边界场景

- [ ] 学号重复、待审批申请重复提交、非活跃会员退会、重复退会均返回 409 且提示明确
- [ ] 已处理申请再次审批返回 409，不产生二次会员创建或状态变更
- [ ] 会员类型、会员状态、申请状态、审批动作传入非法枚举值时返回 400
- [ ] 手机号或邮箱格式不合法时返回 400，并指出具体字段
- [ ] 查询、修改、删除不存在的会员返回 404 并提示“会员不存在”
- [ ] 会员列表无匹配结果时返回 `total=0`、`records=[]`，前端展示空状态而非报错
- [ ] 审批列表未指定类型时，仅返回入会/退会申请，不混入集训报名、赛事报名
- [ ] 分页参数 `page<1` 或 `size<1` 时按默认值处理，`size>100` 时按 100 处理
- [ ] 已逻辑删除的会员不可再被查询、修改或审批，相关操作均返回 404
- [ ] 退会审批通过后，该会员的历史训练、竞赛记录仍保留在档案中，不因角色清空而丢失

## 4. 术语定义

| 术语 | 定义 |
|------|------|
| 会员 | 在协会管理模块中拥有唯一学号档案的自然人，是训练、竞赛、考核等业务的主数据 |
| 普通会员 | 观察会员、正式会员、竞赛实验室成员的统称 |
| 管理会员 | 队长、干事、助理教练、部长/副部长、会长/副会长、指导老师的统称 |
| 观察会员 | 新入会、处于观察期且权限受限的会员，完成考核后可转为正式会员 |
| 竞赛实验室成员 | 协会精英竞赛队员，可参加高强度专项训练与 XCPC 等赛事 |
| 会员类型 | 会员身份分类，取值 `OBSERVE_MEMBER` / `MEMBER` / `LAB_MEMBER` |
| 会员状态 | 会员生命周期状态，取值 `ACTIVE` 活跃 / `INACTIVE` 不活跃 / `RESIGNED` 已退会 / `REMOVED` 已除名 |
| 入会申请 | 未入会用户提交的加入协会申请，申请类型为 `JOIN_MEMBER` |
| 退会申请 | 会员主动提交的退出协会申请，申请类型为 `RESIGN` |
| 除名 | 协会因违规等原因强制将会员移出，会员状态置为 `REMOVED` |
| 逻辑删除 | 不物理删除数据，仅将 `deleted` 标记为 1，保留历史记录供追溯 |
| 会员档案 | 聚合基本信息、角色、训练记录、竞赛成绩、考核记录、奖惩记录的只读视图 |
| 角色层级 | 基于 RBAC 的角色继承关系，高权限角色自动拥有低权限角色的能力 |
| 考核 | 对会员学期注册、训练成果或观察期表现进行的评定，包含成绩、及格线与审核结果 |
| 综测 | 学生综合素质测评，本模块仅预留奖惩记录作为证明材料来源，不做自动加分 |
